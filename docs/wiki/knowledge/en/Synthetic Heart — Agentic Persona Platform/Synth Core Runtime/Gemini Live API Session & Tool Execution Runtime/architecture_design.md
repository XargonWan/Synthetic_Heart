Four cooperating modules form a layered runtime around the Google `google-genai` SDK:
- `live_session_manager.py` is the central orchestrator. `LiveSessionManager` maintains one `LiveSessionState` per guild (session_id, channel_id, active flag, receive task, send buffer, epoch counter). It owns lifecycle (`start_session`, `stop_session`), audio buffering with a periodic `_audio_flush_loop` every 200ms, manual VAD via `activity_start`/`activity_end`, context-window compression, session resumption handles, and proactive reconnect before the ~10-minute server timeout.
- `live_tool_executor.py` is an engine-agnostic bridge: it receives `LiveEvent.TOOL_CALL` events from any live engine, runs them through `core.action_parser.run_action` with a configurable timeout, and sends results back via `engine.send_tool_response`. Supports sequential or concurrent execution via `asyncio.gather`.
- `live_tool_registry.py` builds `ToolManifest` objects from the SyntH action registry (`get_action_plugin_instructions`), converting payload/schema-based actions into `ToolParameter` lists and exposing adapters to wire-format declarations per engine family.
- `live_api_logger.py` provides a dedicated file logger (`logs/live_api.log`) with separate `log_live_send`, `log_live_recv`, and `log_live_session_event` helpers using daily-rotating handlers.

Dependency direction: `live_session_manager` imports `LiveToolExecutor` and the logger; `live_tool_executor` depends on `plugins.live_base.LiveEngineBase` but not on the session manager; `live_tool_registry` depends only on the action parser and schema converter. The session manager exposes a singleton accessor (`get_instance`) for convenience across tests and other subsystems.
