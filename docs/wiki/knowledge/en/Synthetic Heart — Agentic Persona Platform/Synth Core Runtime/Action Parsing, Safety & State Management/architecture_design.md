Four cooperating modules form the action pipeline:
- `action_parser.py` is the central orchestrator: it discovers supported action types via the validation registry, legacy plugins, and interface registries; normalizes payloads (coerces quoted numbers, aliases text fields, unescapes mojibake); delegates validation to the centralized `validation_registry` plus legacy plugin/interface validators; enforces restricted-action policies via `image_processor.RESTRICT_ACTIONS`; and coordinates retry/correction loops with per-thread retry tracking.
- `action_safety.py` implements a policy engine that decides whether an action may auto-execute based on declared `security_level`, `external_effects`, origin (`from_cortex` vs human), and config-driven modes (`SYNTH_AUTONOMY_MODE`, `AUTONOMY_ALLOWED_SECURITY_LEVEL`, `GRILLO_ALLOWED_*`). All configuration keys are registered through `config_registry.get_var` at import time.
- `action_schema_converter.py` normalizes between legacy action definitions (`description`/`required_fields`/`optional_fields`) and the new format (`schema`/`brief`/`examples`), exposing helpers for LLM prompt generation and corrector feedback.
- `action_state_manager.py` provides a thread-safe async stack (`ActionStateManager`) with priority-based phase transitions (`IDLE` < `WRITING` < `TALKING` < `CORRECTING` < `THINKING`) and callback notifications, exposed as a singleton via `get_action_state_manager()`.

Dependency direction is one-way: `action_parser` depends on `action_safety`, `action_schema_converter`, and `action_state_manager`; the latter three have no intra-module dependencies. Cross-cutting concerns (plugin/interface registries, config, logging) are accessed lazily via imports inside functions to avoid circular imports.
