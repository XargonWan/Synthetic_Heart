The module is split into six focused files with a clear dependency direction:
- `core/db.py` is the central runtime facade: it resolves the target backend (`mariadb` vs `postgres`) from environment/config, manages per-event-loop connection pools via `aiomysql` or `asyncpg`, wraps connections in a `_ConnProxy` that intercepts `close()` to return connections to the pool, and exposes `get_conn()`, `get_pool()`, `get_named_postgres_pool()`, and DSN builders.
- `core/db_backends.py` implements the PostgreSQL compatibility layer: `translate_postgres_sql()` rewrites MariaDB dialect (REPLACE INTO, INSERT IGNORE, ON DUPLICATE KEY, JSON functions, DATETIME/TIMESTAMP types) into Postgres-compatible statements, and `PostgresCompatConnection`/`PostgresCompatCursor` present an aiomysql-like cursor API over asyncpg.
- `core/migrations.py` holds idempotent startup migrations (drop legacy tables, rename reserved-word columns, de-duplicate diary segments) registered in `_STARTUP_MIGRATIONS` and executed via `run_startup_migrations()` during boot.
- `core/db_backup.py` builds `DatabaseBackupPlan` objects for `pg_dump`/`mysqldump`, runs them synchronously in a thread via `asyncio.to_thread`, and provides a background scheduler task controlled by `SYNTH_DB_BACKUP_ENABLED` / `SYNTH_DB_BACKUP_INTERVAL_HOURS`.
- `core/db_cutover.py` orchestrates pre-migration backups and then delegates to `MainDbMigrator` for legacy MySQL data and to a dedicated SOUL table migrator; state is persisted to a JSON file under `SYNTH_DB_CUTOVER_STATE_PATH`.
- `core/main_db_migration.py` defines `TableMigrationSpec` entries plus per-table normalizers (`_normalize_*_row`) that coerce MariaDB values (timestamps, booleans, JSON, TIME strings) into asyncpg-compatible types, and drives batched upserts ordered by `MIGRATION_ORDER`.

Dependency direction: `db_cutover` → `main_db_migration` + `db_backup` + `db`; `migrations` → `db`; `db_backup` → `db`; backends are isolated behind `db_backends` so `db.py` can fall back to `aiomysql` when `asyncpg` is absent.
