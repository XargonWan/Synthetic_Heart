Five cooperating modules form the embodiment core around a single persistent entity (SyntH) inhabiting external worlds via pluggable connectors:
- `vessel_registry.py` exposes a `VesselRegistry` singleton (`VESSEL_REGISTRY`) that lazily imports connector modules by dotted path on demand, caches instances, and supports capability-based discovery. Connectors register themselves at import time via the module-level `register_vessel_connector()` helper.
- `vessel_session_manager.py` owns the embodiment session lifecycle: `start_session`/`end_session`/`suspend_session` persist an in-memory `experience_buffer` (JSON array) in `vessel_sessions`, flush it to `vessel_diary` only at session end, and expose a three-state `has_active_session()` (CONNECTED/RECONNECTING/ENDED) driven by an injectable liveness probe from the interface layer.
- `vessel_beat.py` is pure and side-effect-free: it builds structured prompts for the slow volition will-beat, the faster action-beat, and post-damage appraisal, plus config-resolvers for all intervals; scheduling/enqueue wiring lives in `interface.vessel_interface`.
- `vessel_diary_compactor.py` performs chunked LLM-driven summarisation of either the legacy autobiographical buffer (`compact_session`) or the operational activity-log recap (`compact_activity_recap`), both falling back to deterministic plain-text when the Cortex engine is unavailable.
- `vessel_focus.py` provides the shared `is_vessel_turn()` structural detector used across history/prompt/recon layers.
- `vessel_goal_debrief.py` builds the bounded post-session goal debrief input from persisted vessel activity and goal state; it is a data/debrief helper, not an Agent-Lane task.

The vessel plugin owns world-facing policy: action exposure follows live connection state, the whitelist derives hardcoded vessel/world patterns plus configurable core extras, and world-specific actions remain connector-owned. The generic Goals plugin stores one active free-text objective per `(scope, game, world)` tuple; Minecraft's base/quest/target modules translate structural world state into progression actions without keyword-driven routing. Dependency direction is strictly inward: `vessel_session_manager` calls into `vessel_diary_compactor` only at end-of-session (lazy import inside `_compact_and_store`), and both use `core.db.get_conn_ctx()` for async MySQL access. The session manager accepts optional callbacks (`set_compaction_handler`, `set_liveness_probe`) so the plugin/interface layers can plug in behavior without core importing them — keeping this module free of Agent-Lane/Drone dependencies.
