Five cooperating modules form a layered pipeline:
- `media_dispatcher.py` is the single async entry point (`dispatch_media`) that routes incoming files by MIME type through a fixed escalation order: Auris STT for audio/*, Iris vision for image/*/video/*, then a Live-engine fallback via `LIVE_REGISTRY.find_engine_by_capabilities({"input": True})`. Subsystems can be bypassed in "inline" mode via `_is_subsystem_inline`, which checks both the live plugin instance and the config registry.
- `media_extract.py` provides file-based helpers for video transcription: ffmpeg-backed `extract_audio_from_video` producing 16 kHz mono WAV under `tmp/recon_media/`, and `fetch_youtube` using yt-dlp to either grab existing subtitles (fast path) or download audio for STT, returning a `YouTubeFetchResult` whose caller must `cleanup()`.
- `multimodal_attachment.py` bridges interface-specific messages (Telegram/Discord) into a unified `{mime_type, data (base64), filename}` list. It defines supported MIME sets, performs ffmpeg-based audio extraction from videos, and decomposes videos into temporally aligned frame+audio chunks via `decompose_video_to_frames_and_audio`, using ffprobe for dynamic FPS computation against a token budget.
- `image_processor.py` implements access control around image handling via an `ImageProcessor` class gated by the `RESTRICT_ACTIONS` config var (`off` / `trainer_only` / `deny_all`), integrating with `interfaces_registry.is_trainer` and forwarding to `core.auto_response.request_llm_delivery`.
- `media_url_utils.py` derives client-facing HTTP URLs from generated audio filesystem paths, resolving whether the output dir lives under `/static` or an alternate `/media` mount based on `VOX_OUTPUT_DIR`.

Dependency direction is one-way: interfaces → dispatcher → engines; extract/multimodal are leaf utilities invoked by higher layers; no circular imports are introduced — lazy imports (`from core.core_initializer import PLUGIN_REGISTRY`, `__import__(mod)`) are used deliberately to avoid circularity.
