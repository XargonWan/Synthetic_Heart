- Provider renderers are implemented as stateless classes holding only the `PromptRequest` instance, with separate `render()` / `render_with_*()` methods and static `parse_*_response()` methods for response normalization.
- Tool declarations are converted to provider schemas via dedicated helper functions (`_manifest_to_openai_schema`, `_manifest_to_anthropic_tool`, `_manifest_to_gemini_tool`) that share a common `tool_parameter_schema` utility, keeping schema conversion centralized.
- Configuration variables are declared through `register_exposed_var(key, label, default, value_type, ui_type, ...)` calls grouped under a `register_all()` function executed at module import time, with each var tagged by `scope` and `component` for UI grouping.
- Heavy or circular dependencies are deferred via lazy imports inside functions (e.g., `from core.prompt_request import Turn` inside `_history_to_turns`, `from core.action_schema_converter` inside `minify_actions_block`) to avoid module-load cycles.
- Context and memory entries are normalized through deduplication helpers (`_dedupe_context_segments`, `_sanitize_context_entries`) keyed on casefolded content before being appended to the prompt.
