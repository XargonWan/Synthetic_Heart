Two cooperating subsystems share the `core` package namespace. `config_manager.py` defines the `ConfigRegistry` singleton (`config_registry`) plus `ConfigVar` and `ConfigDefinition` dataclasses; it implements a three-tier precedence (environment variable > persisted DB value > hard-coded default), async `set_value` with listener callbacks, optional component reload hooks, and best-effort persistence via `core.db`. `config.py` is the consumer layer: at import time it registers every application setting through `config_registry.get_var()` (with label, description, group, component, tags, constraints) and exposes typed helpers such as `get_active_cortex_engine`, `get_active_cortex_scope`, `scope_model_override`, and per-path cortex overrides. The two files are tightly coupled — `config.py` imports `config_registry` from `config_manager` and uses it as the single source of truth. `model_config.json` is a minimal static fallback model selector (`{"model": "gpt-4o"}`). `model_manager.py` provides an independent `ModelManager` singleton (`MODEL_MANAGER`) that plugins call `register(ModelSpec(...))` against at import time; it manages a filesystem layout under `SYNTH_MODELS_DIR` (`~/.cache/synth/models/<model_id>/`), writes `.manifest.json` metadata, supports HuggingFace Hub and direct URL downloads with progress callbacks, generates per-language MP3 samples under `res/synth_webui/static/audio/model_samples/`, and exposes a JSON-serializable `catalog()` for the WebUI. Dependency direction is one-way: `config.py` depends on `config_manager`; neither config file depends on `model_manager`, keeping model download logic decoupled from runtime configuration.
