The module is split into two cohesive subsystems sharing the `karada` namespace:

- **Transport layer** (`karada_transport.py`, `karada_ws_transport.py`, `karada_api.py`): `KaradaTransport` in `karada_transport.py` defines an ABC with broadcast methods (`broadcast_animation`, `broadcast_audio`, `broadcast_face`, `broadcast_model`, `broadcast_expression`), a targeted `send_to_session`, `preload_asset`, and `get_connected_sessions`. Two concrete implementations exist: `WebSocketTransport` (in `karada_ws_transport.py`) forwards payloads via a shared `Dict[str, WebSocket]` owned by `SynthWebUIInterface`, and `KaradaApiTransport` (in `karada_api.py`) maintains its own connection map for the `/api/karada/ws` endpoint. The `create_karada_router()` factory builds FastAPI routers under `/api/karada/*`, registers `KaradaApiTransport` with the `KaradaStateServer`, and exposes REST endpoints for state queries, animation manifests, skin listing, asset discovery, and an action POST — all gated by an optional `SYNTH_WEBUI_API_TOKEN` bearer/`?token=` check.

- **Touch-event system** (`karada_touch_events.py`): Records three event types (`environment_tap`, `window_tap`, `synth_touch`) into a `karada_touch_events` table with per-type TTLs (10 min for environment/window, 24 h for synth). Events are deduplicated within a 2 s window, batched behind a configurable flush cooldown, then flushed into chat context via `add_message_to_context`. Groups containing at least one `synth_touch` enqueue a spontaneous LLM turn through `message_queue.enqueue`. A background cleanup task periodically purges expired rows. Body-part names are de-sexualized through a catalog-driven mapping (`karada_touch_zones.json`) falling back to a legacy `_BODY_PART_DESEXUALIZE` dict, controlled by the `KARADA_EXPLICIT_TOUCH` toggle.

Dependency direction: both `WebSocketTransport` and `KaradaApiTransport` depend only on the `KaradaTransport` ABC; `karada_api.py` depends on `karada_transport` and the `KaradaStateServer`; `karada_touch_events.py` depends on `core.db`, `core.chat_context_manager`, and `core.message_queue` but has no reverse dependency on the transport layer.
