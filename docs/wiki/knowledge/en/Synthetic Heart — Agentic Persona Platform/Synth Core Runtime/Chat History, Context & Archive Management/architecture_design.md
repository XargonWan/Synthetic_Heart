The module is split into four cooperating layers:
- In-memory context: `chat_context_manager.py` owns two global `deque` maps keyed by `interface_path` — a conversational `_context_memory` (bounded by `CHAT_HISTORY_LIMIT`) and a separate `_perception_memory` ring buffer for Synth's autonomous vessel perceptions, plus an alias-resolution layer (`CONTEXT_LINK_MAP`) that unifies lanes.
- Persistence layer: `chat_history_cache.py` provides async CRUD against the `chat_history_cache` MySQL table via `core.db.get_conn_ctx`, handling timestamp normalization to UTC, JSON metadata serialization, short-window deduplication on write, and live-session broadcast through `LiveSessionManager`.
- Prompt assembly: `history_engine.py` defines the `HistoryEngine.build_context` pipeline that merges current-chat, recent-chats, unified cross-interface history, plugin contributions (`HistoryContribution` from `history_types.py`), thoughts, memories, and tags placeholders, applying verbosity limits, deduplication via SHA-256 of normalized text, and vessel-focus scoping.
- Archives: `chat_archives_db.py` stores full conversation snapshots in a `chat_archives` table; `chat_archives.py` is a thin compatibility shim re-exporting those functions under the legacy import path.
- Recent chats tracking: `recent_chats.py` maintains a `recent_chats` DB table plus an in-memory `_metadata` dict and a `chat_paths.json` file mapping chat IDs to human-readable paths, with DB failures falling back gracefully to memory.

Dependency direction is one-way: `chat_context_manager` → `chat_history_cache` → `core.db`; `history_engine` reads both the in-memory context map and the cache; archives and recent-chats are independent persistence utilities consumed by higher layers. All modules use lazy imports (e.g. `from core.chat_history_cache import ...` inside functions) to avoid circular imports.
