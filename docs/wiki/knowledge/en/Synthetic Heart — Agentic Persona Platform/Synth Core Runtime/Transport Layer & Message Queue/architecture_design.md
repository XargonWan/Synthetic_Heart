The module is split into two complementary layers. `message_queue.py` implements the global `asyncio.PriorityQueue`-backed message bus: `enqueue()`/`enqueue_and_wait()`/`enqueue_low_priority()` normalize incoming messages (mention checks, blocklist, rate limiting, animation state broadcast), assign one of the semantic priority bands (`PRIORITY_EMERGENCY`..`PRIORITY_LOW`), and push items onto a shared queue whose consumer loop runs in the event loop that created it. It also prunes stale autonomous vessel perceptions per world scope so player chat is never delayed by background beats. `transport_layer.py` is the universal send/receive adapter: `extract_json_from_text()` robustly parses LLM JSON output through multiple repair passes (control-char stripping, smart-quote normalization, unescaped-quote escaping, `json_repair` fallback) and `_call_interface_send()` retries calls against different interface signatures (positional payload vs keyword args, optional `message_thread_id`). The Grillo action checker integration lives here as a fire-and-forget background task. `message_sender.py` is a thin Telegram-specific dispatcher that routes content types (audio/document/voice/photo/video/sticker/text/file) to the appropriate bot method with audio↔document fallbacks. `response_proxy.py` holds a short-lived per-user pending-target map for training flows, and `say_proxy.py` is a deprecated no-op shim kept for import compatibility. Dependency direction is one-way: interfaces call into this layer; the layer imports from `core.config_manager`, `core.logging_utils`, `core.core_initializer`, and plugin registries but nothing in those modules depends back on these files.
