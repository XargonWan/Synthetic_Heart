The `core/` package is the application root that wires all subsystems through a strict initialization order in `core_initializer.CoreInitializer.initialize_all()`: (1) registries are created first so every child can register itself; (2) external endpoints are pre-registered before the Cortex engine loads so `ext_*` engines are discoverable; (3) the Cortex engine is loaded, then generic plugins and core actions are discovered; (4) DB tables are ensured and config is eagerly loaded from the database with listener notifications; (5) persona manager and chat context manager are initialized; (6) interface modules are auto-discovered and their instances started as background tasks. Children communicate exclusively through shared registries (`command_registry`, `tool_registry`, `interface_registry`, `cortex_registry`, `live_registry`, `vessel_registry`, `external_endpoints.registry`) and through the central `transport_layer` message queue plus the `chat_context_manager`. Cross-cutting concerns (logging, JSON helpers, timezone/calendar utilities, abstract context, rate limiting, validation registry) live in flat `core/*.py` files consumed uniformly by every child module. The WebUI templates under `webui_templates/` provide the admin surface for managing all of these components at runtime.
