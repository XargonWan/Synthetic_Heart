The module is organized into three parallel subsystems under `engines/`, each following the same plugin discovery pattern:
- `agent/` — agent backends; `agent_base.py` defines `discover_and_register()` which scans the directory with `pkgutil.iter_modules`, skips packages/private/_base modules, imports each remaining module, looks for a `PLUGIN_CLASS` attribute, and registers it via `registry.register_engine_module(cortex='agent', ...)`.
- `external_engines/` — multi-capability providers (LLM, STT, TTS); `external_engines_base.py` reads per-module `ENGINE_CAPABILITIES` (`llm`/`stt`/`tts` booleans) to decide whether to register with `CortexRegistry`, `AurisRegistry`, or `VoxRegistry`, using `PLUGIN_CLASS`, `ENGINE_CLASS`, and `VOX_ENGINE_CLASS` attributes respectively. A nested `dev/` subpackage is conditionally scanned when `dev_enabled=True`.
- `live/` — real-time multimodal engines; `live_base.py` provides both the same discovery loop and a `LiveSessionManager` singleton that owns automatic voice routing, per-path cortex overrides, and rejoin timers.

Each concrete engine module exposes class-level metadata (`PLUGIN_CLASS`, `ENGINE_LABEL`, optional `CAPABILITIES`, `MAX_SESSION_SECONDS`) so the base discoverers can register them without explicit configuration. Dependency direction is one-way: engine modules depend on `core.*` registries/logging/config, never the reverse. The package `__init__.py` re-exports the three subsystems as top-level subpackages.
