- Engine subclasses declare a class attribute `display_name` and implement exactly one abstract core method (`transcribe`, `describe_image`, `generate_tts`, or the async session methods), leaving lifecycle hooks as no-op defaults.
- Plugins register themselves at import time using `core.core_initializer.register_plugin(<id>, self)` and expose configuration options through `core.variables_engine.register_exposed_var` with explicit `scope`, `component`, `value_type`, and `ui_type` fields.
- Action-capable plugins implement the trio `get_supported_action_types() -> list[str]`, `get_supported_actions() -> dict` (with `required_fields`, `optional_fields`, `description`, and optional `security_level`/`external_effects`), and `execute_action(action, context, bot, original_message)` returning a status dict.
- Each plugin directory ships a `<name>.guide.md` alongside the implementation, referenced from `get_metadata()["guide"]` so the WebUI can display user-facing documentation.
- Cross-plugin discovery uses the central `PLUGIN_REGISTRY` from `core.core_initializer` rather than direct imports, allowing optional features (e.g., Grillo beat plugins, history_evaluator) to be loaded lazily and fail gracefully.
- Logging goes through `core.logging_utils` functions (`log_info`, `log_debug`, `log_warning`, `log_error`) instead of the standard `logging` module, keeping log output consistent across the application.
