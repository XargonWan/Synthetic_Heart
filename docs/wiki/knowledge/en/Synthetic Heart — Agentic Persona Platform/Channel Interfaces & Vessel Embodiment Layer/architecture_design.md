The module is organized as a flat registry of independent channel interfaces plus two cross-cutting utilities:
- Per-channel packages (`discord_interface/`, `telegram_bot/`, `matrix_interface/`, `fluxer_interface/`, `openai_api_server/`) each contain a `*_interface.py` implementation and an `__init__.py` shim that rebinds `sys.modules` so legacy import paths like `interface.telegram_bot` still resolve to the submodule. Each package ships its own `guide.md` and icon asset.
- Top-level modules: `vessel_interface.py` implements the duck-typed VesselInterface contract (`display_name`, `get_interface_id()`, `get_supported_actions()`, `send_message()`, `start()`/`stop()`, `on_world_event()`) used by world connectors; `message_send_utils.py` provides shared retry/cooldown/dedupe helpers for outbound sends; `minecraft_provisioner.py` manages the Node.js Mineflayer bridge subprocess lifecycle.
- All interfaces register themselves via `core.core_initializer.register_interface` with a stable id (`discord_bot`, `matrix_chat`, `fluxer_bot`, `ollama_serve`, `vessel`). The vessel interface is hidden from the WebUI (`hidden_from_ui = True`) and communicates with the core through `core.message_queue`, `core.vessel_session_manager`, and `core.chat_context_manager` rather than direct agent calls.
- Dependency direction is one-way: interfaces depend on `core.*` subsystems but never the reverse; the vessel interface additionally depends on `plugins.vessel_plugin` only at call sites (lazy imports inside methods).
